# NeuroPP: ThermoMPNN + SWARM

Пилотный эксперимент по прогнозированию изменения стабильности белка при одиночной аминокислотной замене. Проверено, помогает ли дополнительная рекуррентная обработка с общей сводкой состояний улучшить прогноз поверх замороженных признаков ThermoMPNN.

**Основной результат:** SWARM получил наименьший средний test macro MAE, однако устойчивое преимущество повторного пересчёта общей сводки не установлено. Разница относительно контроля `static` мала, а её 95% bootstrap-интервал включает ноль.

## Подготовка и запуск

Команды выполняются из корня репозитория. Окружение и тетрадки рассчитаны на CPU.

```bash
conda env create -f environment.yml
conda activate NeuroPP

git clone https://github.com/Kuhlman-Lab/ThermoMPNN.git external/ThermoMPNN
git -C external/ThermoMPNN checkout 370f76ec62bd929f7425e311d8df04a0d094990f

mkdir -p data/megascale
curl -fL https://zenodo.org/api/records/7992926/files/Processed_K50_dG_datasets.zip/content -o data/megascale/Processed_K50_dG_datasets.zip
curl -fL https://zenodo.org/api/records/7992926/files/AlphaFold_model_PDBs.zip/content -o data/megascale/AlphaFold_model_PDBs.zip
```

Тетрадки запускаются последовательно с интерпретатором окружения `NeuroPP`. `01_baseline.ipynb` — необязательная техническая проверка; `02_swarm_experiment.ipynb` — полный эксперимент. Необходимые файлы извлекаются из архивов автоматически.

Веса обученных голов не включены в репозиторий. Для повторной оценки опубликованных моделей нужны исходные checkpoints; новый запуск выполняет 40 обучений. Перед новым запуском измените `RUN_NAME` во второй тетрадке, чтобы сохранить опубликованные результаты в `results/swarm_final/`.

## 1. Задача и соглашение о знаке

Вход — последовательность и структура исходного белка (WT), позиция замены и новая аминокислота. Выход — прогноз ΔΔG в ккал/моль.

Положительное ΔΔG означает **дестабилизацию**, отрицательное — стабилизацию:

$$
\Delta\Delta G = \Delta G_{\mathrm{unfold}}^{\mathrm{WT}} - \Delta G_{\mathrm{unfold}}^{\mathrm{MUT}}.
$$

В данных MegaScale целевая метка преобразуется как `ddg_exp = -ddG_ML`. Положительная метка соответствует мутанту, которому требуется меньше энергии для разворачивания. Модель обучается предсказывать этот эффект по данным.

## 2. ThermoMPNN

[ThermoMPNN](https://doi.org/10.1073/pnas.2314853121) использует знания модели ProteinMPNN для прогноза стабильности. ProteinMPNN первоначально обучена подбирать аминокислотную последовательность, совместимую с заданной трёхмерной структурой (Обратный Фолдинг).

[ProteinMPNN](https://doi.org/10.1126/science.add2187) представляет структуру как граф (узлы остатки, ребра - связи между соседями). 

ThermoMPNN извлекает эти представления и передаёт их небольшой выходной части с LightAttention и MLP, обученной на данных стабильности. В используемой конфигурации представление каждого остатка имеет 384 компоненты: два последних состояния декодера по 128 и WT-эмбеддинг размерности 128.

Голова выдаёт 21 оценку на позицию: для 20 стандартных аминокислот и символа `X`. Для замены в позиции $i$ прогноз вычисляется как:

$$
\widehat{\Delta\Delta G}_{i,a\to b} = s_{i,b} - s_{i,a}.
$$

**Почему выбрана для первого пилота.** Открытые исходники, готовые веса и опубликованное разбиение данных. Структурные признаки можно извлечь один раз и заморозить, а небольшую выходную голову заменить. Это позволяет исследовать конкретный механизм обработки признаков при доступных вычислительных ресурсах.

## 3. SWARM

[SWARM](https://arxiv.org/abs/1906.09400) — рекуррентная сеть для обработки наборов элементов. В нашем случае один элемент, или агент, соответствует аминокислотному остатку. Он получает собственные признаки $x_i$ и хранит скрытое состояние $h_i$ и память $c_i$. Обучаемые веса общие для всех остатков и шагов.

На каждом шаге состояния обновляются с учётом входных признаков, предыдущих состояний и общей сводки. В этом пилоте сводка — среднее скрытых состояний остатков одного белка:

$$
\bar h_t = \frac{1}{L}\sum_{j=1}^{L}h_{j,t}.
$$

Входные признаки в течение прохода постоянны. Изначально $h_i=c_i=0$; различия состояний возникают из различий признаков. Первый шаг обрабатывает остатки индивидуально, со второго становится доступна общая информация. При предсказании обновляются состояния, а веса остаются фиксированными. Это поведение соответствует [авторской реализации](https://github.com/zalandoresearch/SWARM/blob/master/swarmlayer.py). 

Почему этот механизм подходит для проверки:

- Обрабатывает белки различной длины одной общей ячейкой.
- Позволяет уточнять представление остатка с учётом сводки по всему белку.
- Разделяемые веса сохраняют компактность модели; при фиксированной ширине стоимость одного обновления дополнительной SWARM-головы растёт линейно с числом остатков.
- Эквивариантен перестановке строк готовых признаков (выходные строки переставляются согласованно). 

Средняя сводка сжимает информацию и не описывает каждую пару остатков отдельно. 

Проекция признаков, три шага и выход ΔΔG — решения данного пилота. 

## 4. Научный дизайн

### Гипотеза и контрольные сравнения

Гипотеза: повторный пересчёт общего контекста помогает точнее оценивать эффект мутации, чем однократное получение общей информации при сопоставимой архитектуре.

Пилот исследовательский: набор контролей и число seed уточнялись на train/validation до оценки test. Формальной предварительной регистрации не было.

Все новые головы получали одну матрицу замороженных признаков $L\times384$ и обучались с нуля. Они заменяли выходную часть ThermoMPNN. Исходная модель целиком оставалась замороженной.

| Вариант | Обработка признаков | Обучаемых параметров |
|---|---|---:|
| ThermoMPNN | Готовый checkpoint; фиксированный ориентир | 0 |
| `mlp` | Независимая обработка каждого остатка: 384 → 32 → 256 → 21 | 26 165 |
| `self` | Рекуррентная голова; контекстная ветвь получает собственное состояние остатка | 26 101 |
| `static` | Общая сводка после первого обновления используется до конца прохода | 26 101 |
| `swarm` | Общая сводка пересчитывается между обновлениями состояний | 26 101 |

В рекуррентных вариантах размер проекции, скрытого состояния и памяти — 32; число обновлений — 3. Выходная линейная голова получает конкатенацию $h_i$ и $c_i$. В `static` градиент через сохранённую сводку не обрывается.

| Сравнение | Проверяемый вопрос |
|---|---|
| ThermoMPNN → новые головы | Полезна ли замена выходной части и её новое обучение? |
| `mlp` → `self` | Полезна ли рекуррентная обработка относительно простой головы? |
| `self` → `static` | Полезно ли добавить общую информацию? |
| **`static` → `swarm`** | **Полезен ли повторный пересчёт общей сводки?** |

Последнее сравнение — основное: у вариантов одинаковы структура параметров, число шагов и начальные веса при одинаковом seed. При трёх шагах различие возникает в третьем обновлении: `static` использует среднее после первого шага, `swarm` — после второго. Сравнение с исходной ThermoMPNN само по себе не выделяет эффект роевого обмена.

### Данные и проверки

MegaScale — экспериментальные оценки стабильности из работы [Tsuboyama et al.](https://doi.org/10.1038/s41586-023-06328-6), полученные с помощью cDNA display proteolysis. Данные и структуры AlphaFold доступны на [Zenodo](https://zenodo.org/records/7992926).

Использовано официальное разбиение ThermoMPNN **по белкам**: 239 train, 31 validation, 28 test. Сохранено разбиение авторов.

Оставлены одиночные замены между стандартными аминокислотами с конечной числовой меткой. Проверены единственность WT-последовательности, её совпадение с PDB, диапазон позиции, WT-буква и полная последовательность мутанта. Использованы одноцепочечные структуры с полными координатами.

На подготовительном этапе прогнозы из извлечённых признаков совпали со штатным вызовом ThermoMPNN для пяти мутаций 1A32. В первой тетрадке MAE этих примеров составила 0.2383 ккал/моль. 

### Обучение и итоговая оценка

- Четыре новые головы обучались на seeds 42–51: **40 отдельных обучений**. Для рекуррентных вариантов одинаковый seed задавал одинаковые начальные веса и порядок train-белков.
- Оптимизатор Adam, learning rate 0.001, 40 эпох. Каждый белок проходил один раз за эпоху; один шаг оптимизатора использовал один белок и среднюю MSE по его мутациям. Белки получали одинаковое число шагов, независимо от количества мутаций.
- Для каждой головы сохранены веса лучшей эпохи по **validation macro MAE**. Validation использовалась для выбора checkpoint, поэтому её результаты не являются независимой итоговой оценкой.
- На test оценены сохранённые головы всех десяти seed без переобучения и выбора лучшего seed. Предсказания в ансамбль не объединялись.

Основная метрика — macro MAE:

$$
\mathrm{MAE}_p = \frac{1}{n_p}\sum_{k=1}^{n_p}|\widehat y_{p,k}-y_{p,k}|,
\qquad
\mathrm{macro\ MAE} = \frac{1}{P}\sum_{p=1}^{P}\mathrm{MAE}_p.
$$

Она даёт каждому белку одинаковый вес. Дополнительно рассчитаны pooled MAE и RMSE по всем мутациям. Средние и стандартные отклонения между seed описывают ошибки отдельных обученных моделей.

Для неопределённости разниц сначала усреднили MAE по seed внутри каждого test-белка. Затем выполнили парный bootstrap **по целым белкам**: 10 000 выборок из 28 белков с возвращением, RNG 2026, одинаковые выборки для всех сравнений. Границы 95% интервала — процентили 2.5% и 97.5%. Мутации одного белка не считались независимыми наблюдениями.

### Ожидаемый результат

Поддержкой основной гипотезы было бы положительное `MAE(static) − MAE(swarm)`, согласованное по seed и белкам, с интервалом, исключающим ноль. Улучшение относительно ThermoMPNN без преимущества над `static` не позволило бы приписать выигрыш повторному обмену.

## 5. Полученные результаты

### Validation

Все значения ошибок — в ккал/моль. Std — стандартное отклонение между десятью seed; исходная ThermoMPNN оценена один раз.

| Модель | Средний macro MAE | Std |
|---|---:|---:|
| ThermoMPNN | 0.430518 | — |
| `mlp` | 0.411275 | 0.002213 |
| `self` | 0.404478 | 0.002089 |
| `static` | **0.403343** | 0.001880 |
| `swarm` | 0.403562 | 0.001880 |

Лучший средний результат у `static`. Средняя разница `static − swarm` равна **−0.000219**: SWARM лучше в четырёх seed, хуже в пяти; в одном разница численно близка к нулю. Первоначальное положительное среднее на трёх seed не сохранилось после расширения до десяти.

### Test

| Модель | Средний macro MAE | Std | Средний pooled MAE | Средний pooled RMSE |
|---|---:|---:|---:|---:|
| ThermoMPNN | 0.529062 | — | 0.534775 | 0.717473 |
| `mlp` | 0.524161 | 0.005092 | 0.528500 | 0.713910 |
| `self` | 0.515525 | 0.002670 | 0.520109 | 0.710171 |
| `static` | 0.514592 | 0.004307 | 0.519826 | 0.707061 |
| `swarm` | **0.513064** | 0.005217 | **0.518153** | **0.706672** |

SWARM имеет наименьшую среднюю test-ошибку. Уменьшение macro MAE относительно ThermoMPNN составляет **0.015998 ккал/моль, около 3.02%**; относительно `static` — **0.001528 ккал/моль, около 0.30%**. Проценты относятся к уменьшению ошибки, не к изменению стабильности белка.

При парном сравнении seed SWARM лучше `static` в семи запусках и хуже в трёх. Seed 46 дал разницу 0.014028 ккал/моль — около 92% суммарной разницы десяти запусков. Средний выигрыш остальных девяти составляет приблизительно 0.00014 ккал/моль. Это анализ чувствительности; основной результат включает все десять seed.

После усреднения MAE по seed SWARM лучше `static` на **15 из 28 белков**, хуже на 13; медианный выигрыш — 0.001033 ккал/моль. Эффект неоднороден: максимальный выигрыш на 2BTH равен +0.018529, максимальное ухудшение на HEEH_KT_rd6_0793 — −0.015078 ккал/моль.

### Неопределённость разниц

Положительная разница означает преимущество второго варианта.

| Сравнение MAE | Средняя разница | Нижняя граница 95% CI | Верхняя граница 95% CI |
|---|---:|---:|---:|
| ThermoMPNN − `swarm` | 0.015998 | −0.011507 | 0.043193 |
| `self` − `static` | 0.000933 | −0.005867 | 0.007352 |
| **`static` − `swarm`** | **0.001528** | **−0.001770** | **0.004901** |
| `self` − `swarm` | 0.002461 | −0.004006 | 0.009279 |

**Все интервалы включают ноль.** Этот анализ не устанавливает уверенное направление ни одной из перечисленных разниц.

## 6. Обсуждение и границы вывода

Новые головы дали меньшую среднюю test-ошибку, чем исходная ThermoMPNN. Однако эта разница объединяет эффект архитектуры головы и её нового обучения. 

В основном сравнении `static` и `swarm` эффект мал, порядок моделей различается между validation и test, а test-выигрыш чувствителен к одному seed. В данной конфигурации повторный пересчёт контекста не показал убедительного устойчивого преимущества (признаки могли уже содержать достаточно контекста, средняя сводка могла быть ограничивающей или эффект мог оказаться слишком мал для имеющейся выборки).

Ограничения пилота:

- Проверена одна конфигурация: замороженные признаки, состояния размерности 32 и три обновления. 
- Test содержит 28 белков. 
- Bootstrap описывает разброс по белкам условно на фиксированную панель обученных моделей (не включает совместно неопределённость нового обучения и экспериментальных меток; возможная зависимость родственных белков отдельно не моделировалась).
- Использована одна выборка стабильности; перенос на другие типы белков, эксперименты или условия не проверен. Функциональные эффекты мутаций и динамика белка не оценивались.

## 7. Выводы

1. Связка замороженных признаков ThermoMPNN с новыми MLP и рекуррентными головами работоспособна; согласованность входов и исходных прогнозов проверена.
2. SWARM получил лучший численный средний результат на test, но его преимущество над `static` и исходной ThermoMPNN не подтверждено рассчитанными интервалами.
3. Основная гипотеза о пользе повторного пересчёта общей сводки **не получила убедительной поддержки в этом пилоте**. Результат ограничен выбранной конфигурацией и данными.
