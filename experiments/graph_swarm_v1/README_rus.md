# Mutation-Conditioned GraphSWARM v1

Этапы 1/1.1 подготавливают инфраструктуру; этап 2 реализует фиксированные
архитектуры моделей и синтетические тесты. Обучение на реальных данных, подбор
гиперпараметров, bootstrap-анализ и оценщик защищённых выборок пока не реализованы.
Первый эксперимент завершён; его тетрадки, документация, признаки, веса и
опубликованные результаты сохранены. Машиночитаемый контракт находится в
[protocol.json](protocol.json), фиксированные параметры и пути — в
[config.yaml](config.yaml).

## Научный вопрос

Улучшает ли повторный пересчёт локальных сообщений между остатками из обновлённых
скрытых состояний, обусловленных мутацией, прогноз ΔΔG по сравнению со
структурным контекстом, который вычисляется один раз и затем остаётся постоянным?

Будущее основное сравнение: `graph_static` и `graph_swarm`. Основной эффект:
`protein_macro_MAE(graph_static) - protein_macro_MAE(graph_swarm)`.
Положительная разница означает преимущество GraphSWARM. Protein macro MAE —
среднее MAE по мутациям внутри каждого белка, затем среднее по белкам с одинаковым
весом каждого белка. На этапе 1 этот эффект не оценивается.

GraphSWARM — **рабочее название проекта**: рекуррентная графовая нейронная сеть,
вдохновлённая SWARM mappings. Скрытые итерации **не являются физическим временем**.
Модель **не моделирует молекулярную динамику**. Одно лишь улучшение MAE
**не доказывает физическое распространение энергии, сил или конформационных волн**.

## Данные, происхождение признаков и защита выборок

Используются прежние MegaScale, структуры WT и замороженные признаки
ThermoMPNN / ProteinMPNN размерности `[L,384]`: два скрытых состояния декодера
и WT-эмбеддинг по 128 компонент. Порядок сохраняется из первого эксперимента:
upstream `hidden[:2]`, затем WT-эмбеддинг. Это контекстные представления **до**
LightAttention и выходной головы стабильности. `light_attention`, `both_out` и
`ddg_out` не входят в путь извлечения признаков. Предыдущие прогнозы ΔΔG,
ошибки, веса обученных старых голов и результаты legacy test запрещены как входы.
Соглашение о знаке сохранено: `ΔΔG = -ddG_ML`, положительное значение означает
дестабилизацию, единицы — ккал/моль.

`neuropp.provenance` проверяет закреплённый commit и хеши артефактов,
checkpoint, фактическую заморозку ProteinMPNN и путь до выходной головы.
После загрузки закреплённого ThermoMPNN checkpoint весь `state_dict` загруженной
ProteinMPNN сравнивается с `model_state_dict` исходного закреплённого файла
`vanilla_model_weights/v_48_020.pt`. Требуются одинаковые ключи (включая buffers),
формы, dtype и конечные значения всех тензоров; сравнение — `torch.equal`,
без допуска. Несовпадение останавливает аудит с отчётом о максимальном абсолютном
расхождении. Статус `passed` возможен только при успешном сравнении тензоров;
одна заморозка не доказывает неизменность весов.
Проверка реальных белков сравнивает признаки с существующим кэшем; hooks
запрещают вызов головы стабильности. При отсутствии артефакта статус —
`blocked / missing artifact`, а не `passed`. Проверка только файлов остаётся
`pending` до проверки модели. Автоматических скачиваний нет. Импортируются
определения модели, но не точка входа обучения upstream.

Исходное разбиение: 239 train / 31 validation / 28 test. Прежний test теперь
называется `legacy_test`: он уже изучался и не является новым независимым тестом.
Новое разбиение: **209 train / 31 validation / 30 head_holdout / 28 legacy_test**.
`head_holdout` защищён **для новых голов** и не является полностью независимым
внешним бенчмарком всей системы или её предобученной основы.

В исправлении этапа 1.1 **`1A32.pdb`** исключён из кандидатов `head_holdout`
и оставлен в train: его индивидуальные экспериментальные метки и ошибки явно
показаны в `notebooks/01_baseline.ipynb`. Проверка четырёх разрешённых документов
подтвердила, что это единственный такой белок исходного train. Исправление
разрешено до реализации и обучения GraphSWARM и не основано на его качестве.
В `head_holdout` вместо `1A32.pdb` включён **`2MA4.pdb`**.

Для остальных 238 неизменённых protein_id из исходного train вычисляется
`SHA256(UTF8("graph_swarm_v1:20261004:" + protein_id))`. После сортировки по
`(hash, protein_id)` первые 30 допустимых ID становятся `head_holdout`;
остальные исходные train ID, включая `1A32.pdb`, остаются в train. Итоговые списки
хранятся лексикографически. [Манифест](../../splits/graph_swarm_v1.json)
содержит рецепт, размеры, источник и хеши исходных и новых списков. Существующий
файл проверяется; другое разбиение не перезаписывается. Допустимость учитывает
документированный прежний просмотр; значения меток в хешировании не используются.
Точные дубликаты WT-последовательностей между выборками сообщаются
без переназначения белков. Гомология и степень сходства на этом этапе не проверяются.

Любая будущая загрузка меток разработки должна проходить через
`DevelopmentDataAccess`. Он проверяет фактическую принадлежность protein_id и
весь запрос до вызова читателя меток. Обе защищённые выборки вызывают
`ProtectedLabelAccess`, даже если пользователь указал строку `train`.
Неизвестный ID вызывает `UnknownProteinID`. Реальный файловый метод
`load_label_directory` дополнительно проверяет ID источника по отдельным
метаданным до открытия файлов меток и проверяет WT мутации. Метки возвращаются
отдельно в `MutationLabels`. Владелец предоставляет раздельные файлы
train/validation; общая CSV с защищёнными метками не является разрешённым
источником разработки. Для метаданных есть отдельный контракт `ProteinMetadata`.
Разблокировки нет. Эта защита API не является запретом произвольного чтения
файлов на уровне операционной системы.

## Контракт записи и графа

`ProteinRecord` содержит protein_id, каноническую WT-последовательность,
`features [L,384]`, `ca_coordinates [L,3]`, `seq_pos [L]`, `residue_uid [L]`,
`edge_index [2,E]` и `edge_attr [E,17]`. Дополнительно хранятся буквы остатков PDB
и декодированных признаков для проверки выравнивания. Координаты заданы в Å.
Последовательность остаётся в каноническом порядке; строки массивов можно
совместно переставлять, сохраняя исходные нулевые WT-позиции и UID
`chain:residue_number:insertion_code`. Запрос мутации содержит
`mutation_position`, `wt_index`, `mut_index`; метки никогда не передаются
в построение графа или подготовку входов модели.

По евклидовым расстояниям C-alpha каждый узел выбирает `min(16,L-1)` других
узлов. При равном расстоянии порядок определяется исходной позицией WT,
а не текущим номером строки. Симметричное объединение сохраняется в обеих
ориентациях: `edge_index[0]` — источник j, `edge_index[1]` — получатель i.
Нет петель, повторных направленных рёбер, cutoff-графа или дополнительных
рёбер между соседями по последовательности. Степень может превышать 16;
связность не гарантируется. При L=1 формы `[2,0]` и `[0,17]`; L=0 — ошибка.

17 признаков ребра: 16 Gaussian RBF с равномерными центрами от 2 до 20 Å
включительно, σ=1.2 Å, затем
`log(1+abs(seq_pos_i-seq_pos_j))/log(1+L)`. Расстояния не обрезаются.
Проверяются длины, конечность чисел, WT-выравнивание и отображение остатков.
Локальный адаптер требует одну модель, одну цепь, стандартные аминокислоты и
полные атомы N/CA/C/O. Альтернативные координаты, пропуски и неоднозначное
соответствие вызывают ошибку. Усечения, padding, исправления и скрытого
сдвига индексов нет.

Диагностика содержит min/mean/max степени, число компонент связности,
min/max расстояния рёбер и среднюю долю других остатков, достижимых за 1/2/4 шага.
Начальный остаток исключается; знаменатель L−1, для L=1 доля равна нулю.
У малых белков четыре шага уже могут покрывать все остатки.

Кэш графов находится в `data/graphs/graph_swarm_v1/`; старый
`data/features/thermompnn/` доступен только для чтения. Ключ зависит от ID,
последовательности, координат, отображения остатков, хеша признаков, параметров
графа и версии протокола. Хранятся только граф и контрольные метаданные, без
меток. Записи атомарны; несовместимость и повреждение обнаруживаются по
метаданным, хешам массивов и проверке графа. Повреждение вызывает явную ошибку.
Локальные кэши не добавляются в Git.

## Фиксированная архитектура этапа 2

Три основные модели: `mutation_self`, `graph_static`, `graph_swarm`, T=4.
Вторичный контроль `graph_swarm_t1` отдельно создаётся с T=1. Будущее основное
сравнение остаётся `graph_static` против `graph_swarm`: одинаковые модули,
параметры и ключи/формы `state_dict`; различается только пересчёт сообщений
после обновления скрытых состояний.

Алфавит мутаций: `ACDEFGHIKLMNPQRSTVWY`, индексы 0..19, WT≠MUT.
`q = concat(one_hot(WT), one_hot(MUT), one_hot(MUT)-one_hot(WT))`, форма `[B,60]`.
Дополнительных свойств аминокислот, обучаемых эмбеддингов и меток во входах нет.
Замороженные `[L,384]` признаки проходят линейную проекцию 384→64 с bias и tanh.
MLP мутации 60→64→64 имеет bias в обоих слоях и SiLU только после первого.
ψ(q) добавляется исключительно к строке, где неизменный `seq_pos` совпадает с
позицией мутации. Начальные состояния имеют форму `[B,L,64]`; запросы независимы.

Для ребра j→i вход сообщения — `(h_i,h_j,e_ij)`: получатель, отправитель,
17 неизменных признаков ребра (145 компонент). MLP сообщений 145→64→64
с bias в обоих слоях; attention 145→32→1 с bias в первом слое и **без bias**
в последнем. SiLU стоит только после первого слоя каждого MLP. Устойчивый
softmax нормирует входящих соседей отдельно для каждого получателя и запроса.
Взвешенные сообщения суммируются у получателя; без входящих рёбер сообщение
равно нулю. Используется обычный PyTorch, без внешних графовых библиотек.

Сначала все сообщения вычисляются из Hᵗ, затем все узлы синхронно обновляются
одним `GRUCell(64,64,bias=True)`. Параметры общие для остатков, шагов и запросов.
Dropout=0, BatchNorm=false, LayerNorm=false; дополнительных residual-связей
и глобального вектора внутри рекуррентной динамики нет.
`graph_swarm` пересчитывает значения и attention на каждом шаге.
`graph_static` один раз вычисляет обусловленное мутацией m⁰ **после инъекции**
и использует тот же тензор на всех шагах. Каждый новый forward вычисляет m⁰
заново, без detach и без `no_grad`; градиенты проходят через его построение.

`mutation_self` на каждом шаге подаёт `(h_i,h_i,zeros(17))` в тот же MLP
сообщений, без attention. Это означает **отсутствие обмена между узлами внутри
рекуррентной динамики**. Другие остатки участвуют в финальном среднем readout,
поэтому модель не является изолированным предиктором одного остатка.
Attention зарегистрирован, но не используется. `graph_swarm_t1` использует
те же графовые модули для одного шага. Режим T=1 основных вариантов нужен
для проверки равенства прогнозов и градиентов; основное сравнение остаётся T=4.

Readout объединяет скрытое состояние строки мутации, среднее по всем узлам
и q (188 компонент). MLP 188→64→1 с bias в обоих слоях и SiLU только после
первого выдаёт один скаляр ΔΔG на запрос, форма `[B]`.

| Модель | Шаги | Зарегистрированные обучаемые параметры | Используемые параметры |
|---|---:|---:|---:|
| mutation_self | 4 | 88 033 | 83 329 |
| graph_static | 4 | 88 033 | 88 033 |
| graph_swarm | 4 | 88 033 | 88 033 |
| graph_swarm_t1 | 1 | 88 033 | 88 033 |

Неактивный attention содержит 4 704 параметра. Используемое число описывает
участие модуля в обычном forward с инъекцией; каждый скаляр не обязан иметь
ненулевой градиент на каждом графе, особенно при одном входящем соседе.

## API моделей и диагностика

`MutationGraphModel` находится в `neuropp.models`. Нужен PyTorch ≥2.5,
уже доступный в CPU-окружении NeuroPP; необязательный extra пакета — `models`.
Импорт базовой инфраструктуры по-прежнему не импортирует PyTorch. Установка
и скачивание пакетов на этом этапе не нужны.

```python
model = MutationGraphModel("graph_swarm")
prediction = model(features, seq_pos, edge_index, edge_attr,
                   mutation_positions, wt_indices, mut_indices)
prediction, diagnostics = model(
    features, seq_pos, edge_index, edge_attr,
    mutation_positions, wt_indices, mut_indices,
    return_diagnostics=True,
)
reference_prediction, reference = model(
    features, seq_pos, edge_index, edge_attr,
    mutation_positions, wt_indices, mut_indices,
    return_diagnostics=True, inject_mutation=False,
)
```

Формы входов: `[L,384]`, `[L]`, `[2,E]`, `[E,17]`, `[B]`, `[B]`, `[B]`, L/B>0.
Float32/float64 должны совпадать с dtype/device модели, индексы — целочисленные
тензоры на том же устройстве. Преобразования выполняются явно. Проверяются
формы, конечность, полное отображение `seq_pos`, допустимые позиции и индексы
аминокислот, WT≠MUT, концы рёбер, отсутствие петель и повторных рёбер.
Геометрическая топология и WT-выравнивание остаются ответственностью
`ProteinRecord.validate()` и `MutationQuery.validate(record)` этапа 1;
WT нельзя вывести из контекстных признаков. Синтетическая цепь служит только
тестом головы, реальный граф по-прежнему строится с k=16. Метки и произвольные
аргументы target в forward не принимаются.

Диагностика по умолчанию выключена. Она возвращает H⁰..Hᵀ, сообщения,
attention, q и найденные строки мутаций, сохраняя прогнозы, состояние модели
и градиенты. Возвращаются исходные тензоры с autograd: не изменяйте их и
освобождайте после использования. У static сообщения/attention повторяются
как один и тот же объект; у self attention равен `None`.

Согласованная reference-траектория сохраняет признаки, граф, веса, q и режим
модели и убирает только локальное добавление ψ(q). Будущая мера ответа:
`delta_i^t = ||h_i,injected^t - h_i,reference^t||₂`. q остаётся в readout
обоих проходов. Сравниваются скрытые траектории, не Hᵗ−H⁰. Это инфраструктура
для анализа, не доказательство механизма и не WT molecular dynamics.

`model.checkpoint_configuration()` явно записывает вариант, число шагов,
версию графового протокола и полную архитектуру. Сохраняйте её рядом с
`state_dict`; загрузчик этапа 3 должен проверять оба. Одни ключи тензоров
не различают static/swarm и T=1/T=4. Обучающий pipeline и защищённый оценщик
на этапе 2 не реализуются.

## Ограничения интерпретации и проверка этапа 2

Три реальные графа этапа 1 (`1AOY.pdb`, `1E0L.pdb`, `1I6C.pdb`) достигали
**всех узлов за четыре перехода**: средняя доля других остатков 1.0000.
T=4 не гарантирует локальность информации. Четыре обновления не означают
четыре физические оболочки взаимодействий, физические временные шаги
или распространение молекулярного сигнала. Основной вопрос — помогает ли
пересчёт сообщений из меняющихся обусловленных мутацией состояний по сравнению
с фиксированными обусловленными мутацией сообщениями. Ограничения на цепи
относятся к **добавочному ответу головы при фиксированных признаках**, а не
к receptive field ProteinMPNN.

На этапе 2 запускаются только синтетические тесты этапов 1/1.1 и 2:

```bash
PYTHONPATH=src conda run --no-capture-output -n NeuroPP python -m unittest discover -s tests/graph_swarm_v1 -v
```
